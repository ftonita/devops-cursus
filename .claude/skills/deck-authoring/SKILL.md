# Deck authoring

Каждая тема курса = мануал (полный материал, `manuals/`) + **презентация** (короткая,
«продающая», интерактивная, `site/slides/NN-slug/`). Презентация не пересказывает мануал:
она за 12–16 слайдов / ≈ 15 минут продаёт идею темы и даёт «пощупать» главное руками.
Подробности остаются в мануале, на него ведут ссылки.

## Файлы
- `site/slides/NN-slug/index.html` — слайды (`<section>` внутри `<main class="deck">`), заметки лектора.
- `site/slides/NN-slug/slides.js` — интерактив, специфичный для темы (IIFE, `"use strict"`).
- Стартовая точка: **скопируй `templates/deck/`** и замени NN, SLUG, тему, тексты. Он содержит
  рабочие примеры всех типов слайдов.
- Общее (не копировать, не править без нужды): `site/assets/deck.css`, `deck.js` (движок),
  `cursus.css` (темы + компоненты), `cursus.js` (декларативный интерактив).
- Тема цвета: класс на `<body>` — `theme-git|cicd|docker|flow|k8s|iac|obs|linux|sec|cloud|sre`.
  Новый цвет добавляется в начало `cursus.css`. На слайде можно менять доменную палитру
  классом секции `dom-pg|ng|dk|us|fw|id|gr`.
- Регистрация: запись в `site/topics.js` (slides/minutes обновит `scripts/check-decks.py --update-topics`).

## Нарратив («продающий»)
1. **Титул**: обещание результата (h1, ≤ 8 слов) + `.hook` с болью + 3–6 пунктов `.agenda` + `.stats`.
2. Слайд 2 — **боль → решение** (`.pain` была/стала, `.versus`, аналогия `.analogy`).
3. Дальше 8–12 слайдов: одна мысль = один слайд, заголовок-утверждение
   («Индекс — это черновик коммита», а не «Индекс»).
4. **Минимум 4 интерактивных слайда** на колоду (см. «Интерактив») и минимум 1 тест `.mc`.
5. Слайд про типичные ошибки (антипаттерны) — в формате «что ломается → как правильно».
6. **Финал**: `.flip` вопросы для самопроверки + `.nextup` с кнопками «📖 Мануал», «✅ Квиз» (если есть),
   «☰ Оглавление курса» и анонс следующей темы.
7. Тон: русский, на «вы» или безлично, живо, без канцелярита; термины на английском как в мануале.
   Факты брать из мануала темы и не противоречить ему. Не выдумывать цифры и версии.
8. Каждому слайду — `<aside class="notes">` (2–4 предложения лектору: что сказать, на что нажать).

## Размеры и вёрстка (холст 1600×900)
- Слайд не скроллится: контент обязан помещаться. Текст ≥ 16px, код 15–20px.
- Раскладки: `.body.split` (`.l` + `.r`), `.body.col`, `.grid.g2/g3/g4`, `.versus`, `.pain`, `.steps-row`.
- Не больше ~6 строк прозы и ~14 строк кода на слайд. Много — дели слайд.
- Заголовок: `<div class="sh"><div class="kicker"><span class="n"></span>Раздел</div><h2>…</h2><p class="lede">…</p></div>`.
- Мобильный режим (`body.flow`) включается сам: используй готовые классы, не задавай фиксированных ширин в px > 1000.

## Компоненты (разметка — в templates/deck/index.html)
| Что | Как |
|---|---|
| Код с подсветкой | `<script type="text/x-code" data-lang="bash\|git\|yaml\|docker\|diff\|ini\|conf\|tree\|text" data-title="файл" data-cls="grow\|sm\|xs\|lg">`; блоки `#@ключ` + элементы `data-k="ключ"` = пошаговый фокус по `→` и клику |
| Карточка сущности | `.ent > .ei + div(.et, .ed)`, в `.r.viz` / `.frame` |
| Аналогия / врезка | `.analogy`, `.callout`, `.card`, `.tag`, `code.i` для инлайн-кода |
| Ряд этапов | `.steps-row > .sr` (`button.sr[data-tab]` — кликабельный) |
| Табы/панели | `.tabs > button[data-tab]` или `.steps-row`, панели `[data-pane][data-group]` (cursus.js) |
| Тест | `.mc[data-correct=индекс]` > `.q`, `.opts button`×3–4, `.why`, `.score` |
| Карточка вопрос→ответ | `button.flip[aria-expanded]` > `.q .a .tap` внутри `.qa` |
| Табло метрик | `.kpis > .kpi > b + span` |
| Терминал-симулятор | `.term > .tt + pre#id` (в pre классы `.ok .err .dim .cmd .hi`) |
| Переключатель | `.sw[aria-pressed]` + `.knob`, `.meter > i`, `.order` (чек-лист) — см. `deck.css` |

## Интерактив (≥ 4 на колоду, подбирай по теме)
Примеры, что работает: терминал-симулятор команд с состоянием (git: рабочий каталог/индекс/репозиторий
меняются по кнопкам); пайплайн, где можно «сломать» этап и увидеть остановку; конструктор
Dockerfile/слои с подсчётом кэша; переключатель стратегий (было/стало, график ветвления SVG);
ползунок метрики (частота деплоев → время восстановления); тест `.mc`; flip-карточки; чек-лист.
Правила: всё работает без сети; состояние сбрасывается кнопкой; управление доступно с клавиатуры
(`<button>`, не `<div onclick>`); не использовать `alert`; не ловить `keydown` стрелок и пробела
(их использует движок); анимации ≤ 1 с, учитывать `prefers-reduced-motion` (глобально уже учтено).

## Проверка (обязательно перед коммитом)
```
python3 scripts/check-decks.py NN-slug --shots /tmp/shots   # нужен playwright
```
Скрипт падает, если слайд не помещается в 1600×900, есть JS-ошибка или горизонтальный скролл
на мобильном. Затем **открой 3–4 скриншота** (Read на PNG) и убедись глазами: нет пустых
дыр, выравнивание, контраст, читаемость. Исправляй и перезапускай до зелёного.
После этого: `python3 scripts/check-decks.py --update-topics`.

## Чего не делать
- Не копировать тексты мануала абзацами; не делать слайд-«стену текста».
- Не подключать внешние скрипты/CDN (кроме шрифтов в шаблоне), не добавлять npm-зависимости.
- Не менять `site/assets/deck.js` и общие стили ради одной колоды — если нужен новый общий
  компонент, добавь его в `cursus.css`/`cursus.js` и опиши в этой таблице.
