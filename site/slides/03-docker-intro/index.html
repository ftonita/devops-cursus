простыми словами

«У меня на компьютере работает!» — фраза, после которой у команды начинается плохой день. Docker придуман, чтобы её больше не слышать.

Это вторая, «человеческая» часть темы: в первой мы разбирали Dockerfile, слои и безопасность, здесь — идея и польза. Спросите, кто слышал фразу «у меня работает», и пообещайте: к концу будет понятно, как с ней покончить.

Идея

Docker придумали по образцу грузового контейнера

Название не случайное: «container» — это та самая стальная коробка, в которой возят грузы по всему миру.

⚓ Порт до стандартных коробок

  • Мешки, бочки, ящики — у каждого груза свой размер
  • Каждый груз грузят и крепят по-своему
  • На каждом этапе его перекладывают — часть портится
→

📦 Порт со стандартной коробкой

  • Одна форма для любого груза
  • Кран, поезд, грузовик и корабль работают с ней одинаково
  • Что внутри — порту не важно, коробку не вскрывают
💡
Главная мысльDocker делает то же самое для программ: упаковал один раз — и любой компьютер умеет эту «коробку» запустить, не интересуясь, что внутри.

Расскажите про порт своими словами: раньше грузчики перекладывали всё вручную, потом появилась стандартная коробка. Подчеркните: стандартом стала форма коробки, а не груз. Так же и в Docker: стандартна упаковка.

Проблема

Программа одна, а компьютеры у всех разные

Переключайте режим: смотрите, что происходит с одной и той же программой. Версии условные, для примера.

Код тот же. Отличается всё вокруг него: версии языка, библиотек, настройки. Docker берёт «всё вокруг» с собой.

Сначала покажите «Без Docker»: у разработчика всё работает, у остальных нет, и все виноваты друг в друге. Потом переключите на «С Docker»: окружение едет вместе с программой, поэтому везде одинаково.

Словарь

Четыре слова — и вы понимаете разговоры про Docker

Нажимайте на слова. Сравнение — с компьютерной игрой: установочный файл и запущенная игра.

📝 Рецепт — инструкция по сборке

Текстовый файл: «возьми такую основу, добавь мою программу, запускай вот так».

Аналогия: рецепт блюда или чертёж мебели.

Как выглядит

FROM python:3.12COPY . /appCMD ["python", "app.py"]

🧱 Образ — готовая упакованная коробка

Результат сборки по рецепту. Его нельзя менять, можно только собрать новый.

Аналогия: установочный файл игры. Он один и тот же у всех.

Команда

docker build -t myapp .собрать образ по рецепту

🏬 Склад — где хранятся образы

Туда загружают образы, оттуда скачивают по названию. Самый известный склад — Docker Hub.

Аналогия: магазин приложений для коробок.

Команды

docker push myappdocker pull nginxзагрузить на склад · скачать со склада

▶️ Контейнер — запущенная коробка

Образ, который «включили». Из одного образа можно запустить сколько угодно контейнеров.

Аналогия: запущенная игра. Закрыли и удалили — установочный файл остался.

Команда

docker run nginxзапустить контейнер из образа

Пройдите по четырём кнопкам слева направо: рецепт → образ → склад → контейнер. Главное, что должны унести: образ — неизменяемая заготовка, контейнер — её запущенная копия. Термины на английском оставьте рядом, чтобы студенты узнавали их в документации.

Как устроено

Контейнер — это комната, а не отдельный дом

Виртуальная машина — отдельный дом на своём фундаменте. Контейнеры — комнаты в одном доме с общим фундаментом.

На практике их не противопоставляют: часто контейнеры запускают внутри виртуальных машин — получается и крепкая граница, и лёгкость.

Аналогия: у виртуальной машины свой дом, фундамент и коммуникации — надёжно, но дорого и долго строить. Контейнер — комната в общем доме: быстро, дёшево, но стены тоньше. Цифры из мануала: ВМ — гигабайты и минуты, контейнеры — десятки-сотни МБ и секунды.

Зачем это нужно

Пять ситуаций, в которых Docker экономит день

Нажмите на ситуацию: что было без Docker и как стало.

😖 Без Docker

  • Многостраничная инструкция по настройке, которая устарела
  • День-два на то, чтобы просто запустить проект
  • Спрашивает у соседа, почему не стартует
→

😌 С Docker

  • Скачал проект, выполнил одну команду
  • Проект работает вместе с базой данных
  • Первый день — на задачу, а не на настройку
docker compose up

😖 Без Docker

  • «У меня не воспроизводится» — у каждого своя версия всего
  • Часы уходят на выяснение, чем отличаются компьютеры
  • Баг есть, но поймать его не удаётся
→

😌 С Docker

  • Коллега присылает название образа
  • У вас запускается ровно то же самое окружение
  • Баг воспроизводится — значит, можно чинить
docker run company/app:1.4.2

😖 Без Docker

  • Проекту А нужна старая версия, проекту Б — новая
  • Две версии на одном компьютере спорят друг с другом
  • Пакеты ставятся «поверх» и ломают соседей
→

😌 С Docker

  • У каждого проекта своя коробка со своими версиями
  • Коробки друг о друге не знают и не конфликтуют
  • Переключение между проектами — запуск другой коробки

😖 Без Docker

  • Чтобы попробовать базу данных, её нужно установить
  • После экспериментов остаются файлы, службы, настройки
  • Страшно «засорить» рабочий компьютер
→

😌 С Docker

  • Запустили базу в контейнере, поэкспериментировали
  • Удалили контейнер — компьютер как был
  • Хотите другую версию — запустите другой образ
docker run postgres:17

😖 Без Docker

  • Новая версия сломалась в проде, а старую «надо вспомнить, как ставить»
  • Откат — это ещё один рискованный выкат
  • Простой, нервы, ночные созвоны
→

😌 С Docker

  • Каждая версия — отдельный образ на складе
  • Откат — запуск предыдущей коробки, которая уже проверена
  • Предсказуемо и быстро
docker run app:1.4.1
🍕
Как доставка едыКухня упаковала заказ один раз. Курьер везёт ту же коробку, клиенту не нужно знать рецепт — просто открывает и ест.

Пройдите все пять ситуаций, но спросите зал, какая им ближе. Новичкам чаще всего откликается «первый день в команде» и «у меня не воспроизводится». Идеи про откат и два проекта подкрепляются мануалом: версии образов хранятся на складе, так что предыдущую коробку можно запустить снова.

Как это выглядит в работе

Коробку собирают один раз — а едет она везде

Нажмите на этап, чтобы увидеть, что на нём происходит.

💻 Разработчик пишет код и собирает коробку

Код готов → по рецепту собирается образ с номером версии. Дальше его не меняют.

Команда

docker build -t app:1.4.2 .

🏬 Образ отправляется на склад

Склад хранит все версии: 1.4.0, 1.4.1, 1.4.2… Любую можно скачать позже.

Команда

docker push app:1.4.2

🧪 Тестовая среда скачивает ту же коробку

Тестируют именно то, что поедет к пользователям. Никакой пересборки «под тест».

Команды

docker pull app:1.4.2docker run app:1.4.2

🌍 Та же коробка запускается на сервере

Если что-то пошло не так — запускают предыдущую версию, она лежит на складе.

Команды

docker pull app:1.4.2docker run app:1.4.2
📦 На каждом этапе — одна и та же коробка app:1.4.2. Меняется место, содержимое — нет.

Покажите путь слева направо. Мысль: образ собирается один раз и дальше только переезжает — это и есть «образ неизменяем». Если студенты знакомы с CI/CD, свяжите с первой темой: пайплайн делает это автоматически.

Нажмите «docker compose up» — все три коробки «зажигаются». Объясните: файл описывает, из каких коробок состоит сервис, а Docker Compose поднимает их вместе и сам соединяет. Это и есть «окружение в репозитории»: новичку достаточно одной команды.

Альтернативы

Docker — не единственный способ запускать контейнеры

Как марки автомобилей: разные производители, но дороги одни.

🦭 Podman

Что это: программа, которая запускает контейнеры почти теми же командами: podman run вместо docker run.

Чем отличается: не нужен постоянно работающий «диспетчер» (демон), а запуск без прав администратора (rootless) включён по умолчанию.

Когда выбирают

Когда важна безопасность «из коробки» и нет желания держать фоновый сервис. Образы из Docker запускаются без переделки.

⚙️ containerd и nerdctl

Что это: containerd — «движок», который работает внутри самого Docker. Это отдельный проект, и Kubernetes использует его напрямую.

nerdctl — командная строка в стиле Docker для этого движка.

Когда выбирают

Когда нужен только движок без «обвеса» Docker — например, на серверах с Kubernetes.

☸️ CRI-O

Что это: движок контейнеров, сделанный специально для Kubernetes.

Вы вряд ли запустите его руками: он работает «под капотом» кластера и запускает те же образы.

Когда встретите

В кластерах Kubernetes. Для знакомства с контейнерами он не нужен.

🖥️ Rancher Desktop и Colima

Что это: готовые приложения, чтобы пользоваться контейнерами на ноутбуке с Mac или Windows. Rancher Desktop — с окошком, Colima — из терминала.

Внутри у них контейнерный движок, а снаружи привычные команды.

Когда выбирают

Когда нужен Docker-подобный опыт на ноутбуке без Docker Desktop.
Отдельно есть инструменты, которые только собирают образы (BuildKit, Buildah, Kaniko) — обычно в CI-пайплайне.

Задача слайда — снять страх «а вдруг Docker не тот». Скажите: идея контейнеров шире одного продукта. Для новичка разницы почти нет: команды похожи, образы одинаковые. Выбор чаще диктуют компания, платформа или безопасность.

Альтернативы

Инструменты разные, а образ — один и тот же

Переключайте инструмент: цепочка от команды до запущенной коробки меняется, а образ остаётся прежним.

Переключите три режима. Мысль: у Docker несколько слоёв, у Podman цепочка короче, в Kubernetes движок внутри кластера. Ключевая идея — общий стандарт образа (OCI), поэтому образ, собранный одним инструментом, запускается другим. Kubernetes отказался от прямой работы с Docker, но образы работают как раньше.

Проверка

Два вопроса — что выберете вы?

Коллега собрал образ в Docker. Запустится ли он у вас в Podman?
Почему так. Формат образа стандартизирован OCI, поэтому образ переносим между Docker, Podman, containerd и CRI-O.
Вы записали данные в запущенную коробку, а потом удалили контейнер. Что с данными?
Почему так. Всё, что контейнер записал в себя, исчезает вместе с ним. Данные, которые нужно сохранить, хранят в томах (volumes) — отдельно от коробки.

Дайте 20 секунд на каждый вопрос. Первый закрепляет идею общего стандарта, второй — частую ловушку новичков: контейнер временный, данные надо хранить отдельно.

Ошибки

На чём чаще всего спотыкаются в первый месяц

Что ломается → как правильно.

Хранят базу данных внутри контейнера
Удалили контейнер — пропали данные.
Данные — в томе (volume), отдельно от коробки.
Берут образ с тегом latest
Сегодня одна версия, завтра другая — всё «само» поломалось.
Указывать конкретную версию: postgres:17.
Кладут пароли внутрь образа
Кто скачал образ — тот видит пароль.
Передавать секреты снаружи при запуске.
Запускают «целый компьютер» в одном контейнере
Сложно перезапускать, смотреть логи и менять по частям.
Одна коробка — одна задача: сайт, база, кэш отдельно.
Включают --privileged, «чтобы заработало»
Изоляция снимается, контейнер получает власть над хостом.
Разобраться, чего именно не хватает, и выдать только это.
Берут случайный образ из интернета
Это чужая программа, и неизвестно, что внутри.
Брать официальные образы и проверять их сканером.
