# Глоссарий терминов

Общий глоссарий терминов, встречающихся в мануалах курса. При добавлении
нового мануала — сверяйтесь со скиллом `glossary-sync`: новые термины
добавляются сюда в алфавитном порядке с коротким определением и ссылкой на
мануал-источник.

| Термин | Определение | Источник |
|---|---|---|
| Blue-Green Deployment | Стратегия деплоя: новая версия (Green) разворачивается полностью отдельно от текущей (Blue), трафик переключается разом после проверки. Откат — мгновенное переключение обратно. | [01-cicd-manual](../manuals/01-cicd-manual.MD#стратегии-деплоя) |
| BuildKit | Движок сборки образов Docker, используемый по умолчанию с Docker Engine 23.0: параллелит стадии, поддерживает cache mounts и монтирование секретов. | [02-docker-manual](../manuals/02-docker-manual.MD#архитектура-docker) |
| Canary Deployment | Стратегия деплоя: новая версия сначала получает малую долю трафика; если метрики в норме, доля постепенно растёт до 100%. | [01-cicd-manual](../manuals/01-cicd-manual.MD#стратегии-деплоя) |
| CI (Continuous Integration) | Непрерывная интеграция — частое слияние изменений в основную ветку с автоматической проверкой (сборка, тесты, анализ). | [01-cicd-manual](../manuals/01-cicd-manual.MD#что-такое-cicd) |
| CD (Continuous Delivery) | Непрерывная доставка — автоматическая подготовка релиза, готового к деплою в любой момент; финальное решение о деплое остаётся за человеком. | [01-cicd-manual](../manuals/01-cicd-manual.MD#что-такое-cicd) |
| CD (Continuous Deployment) | Непрерывное развёртывание — автоматический деплой каждого прошедшего проверки изменения в production без ручного подтверждения. | [01-cicd-manual](../manuals/01-cicd-manual.MD#что-такое-cicd) |
| cgroups (control groups) | Механизм ядра Linux, ограничивающий потребление ресурсов процессом или группой процессов — CPU, память, I/O. | [02-docker-manual](../manuals/02-docker-manual.MD#что-такое-контейнеризация) |
| Container (контейнер) | Запущенный экземпляр образа: изолированный namespaces и cgroups процесс с writable-слоем поверх слоёв образа. | [02-docker-manual](../manuals/02-docker-manual.MD#что-такое-контейнеризация) |
| Container Image (образ) | Неизменяемый набор слоёв только для чтения плюс метаданные запуска; шаблон, из которого создаются контейнеры. | [02-docker-manual](../manuals/02-docker-manual.MD#что-такое-контейнеризация) |
| Container Registry (реестр образов) | Хранилище образов с версионированием, правами доступа и API — например, Docker Hub, ECR, Harbor. | [02-docker-manual](../manuals/02-docker-manual.MD#компоненты-подробно) |
| Copy-on-Write (CoW) | Механизм, при котором изменяемый файл копируется в верхний слой только в момент записи — основа writable-слоя контейнера. | [02-docker-manual](../manuals/02-docker-manual.MD#что-такое-контейнеризация) |
| CVE (Common Vulnerabilities and Exposures) | Публичный идентификатор известной уязвимости в ПО. | [02-docker-manual](../manuals/02-docker-manual.MD#компоненты-подробно) |
| Distroless-образ | Базовый образ без shell, пакетного менеджера и лишних утилит — содержит только рантайм приложения, что резко сокращает поверхность атаки. | [02-docker-manual](../manuals/02-docker-manual.MD#компоненты-подробно) |
| Dockerfile | Текстовый файл-рецепт, описывающий сборку образа последовательностью инструкций (`FROM`, `COPY`, `RUN`, `CMD`). | [02-docker-manual](../manuals/02-docker-manual.MD#что-такое-контейнеризация) |
| DORA-метрики | Четыре ключевые метрики зрелости DevOps: Deployment Frequency, Lead Time for Changes, Change Failure Rate, Time to Restore Service. | [01-cicd-manual](../manuals/01-cicd-manual.MD#метрики-эффективности) |
| Feature Flag | Механизм, отделяющий деплой кода от включения фичи для пользователей — фича может быть в проде, но выключена. | [01-cicd-manual](../manuals/01-cicd-manual.MD#best-practices) |
| IaC (Infrastructure as Code) | Подход, при котором инфраструктура описывается и управляется кодом (например, Terraform, Ansible), а не настраивается вручную. | [01-cicd-manual](../manuals/01-cicd-manual.MD#best-practices) |
| Image Digest | Неизменяемый адрес образа по содержимому вида `sha256:...`; в отличие от тега, всегда указывает на один и тот же образ. | [02-docker-manual](../manuals/02-docker-manual.MD#компоненты-подробно) |
| Immutable Artifact | Принцип: артефакт (например, Docker-образ) собирается один раз и переиспользуется на всех окружениях без пересборки. | [01-cicd-manual](../manuals/01-cicd-manual.MD#best-practices) |
| Layer (слой образа) | Результат одной изменяющей файловую систему инструкции Dockerfile; слои неизменяемы, кэшируются и переиспользуются между образами. | [02-docker-manual](../manuals/02-docker-manual.MD#компоненты-подробно) |
| Multi-arch образ | Образ, опубликованный под несколько архитектур (например, `linux/amd64` и `linux/arm64`) и объединённый manifest list под одним тегом. | [02-docker-manual](../manuals/02-docker-manual.MD#практические-примеры-конфигураций) |
| Multi-stage build | Сборка образа в несколько стадий `FROM`, где в финальный образ копируется только результат сборки без компиляторов и dev-зависимостей. | [02-docker-manual](../manuals/02-docker-manual.MD#компоненты-подробно) |
| Namespaces (пространства имён Linux) | Механизм ядра, изолирующий то, что видит процесс: свои PID, сеть, точки монтирования, пользователи. | [02-docker-manual](../manuals/02-docker-manual.MD#что-такое-контейнеризация) |
| OCI (Open Container Initiative) | Стандарты формата образа, среды выполнения и протокола реестра, благодаря которым образы переносимы между Docker, containerd, Podman и CRI-O. | [02-docker-manual](../manuals/02-docker-manual.MD#что-такое-контейнеризация) |
| Provenance (аттестация происхождения) | Машиночитаемые метаданные о том, как и из чего собран образ: репозиторий, коммит, сборочная система. Сама по себе не подписана — buildx прикрепляет её к образу как есть; подпись, если нужна, ставится отдельно (например, cosign). | [02-docker-manual](../manuals/02-docker-manual.MD#практические-примеры-конфигураций) |
| Rolling Update | Стратегия деплоя: инстансы обновляются поочерёдно без простоя; какое-то время сосуществуют две версии. | [01-cicd-manual](../manuals/01-cicd-manual.MD#стратегии-деплоя) |
| Rootless-контейнер | Режим запуска контейнеров без root-привилегий у демона и процесса внутри, сокращающий последствия компрометации. | [02-docker-manual](../manuals/02-docker-manual.MD#частые-ошибки-и-антипаттерны) |
| SAST (Static Application Security Testing) | Статический анализ безопасности кода без его выполнения (например, SonarQube, Semgrep). | [01-cicd-manual](../manuals/01-cicd-manual.MD#этапы-пайплайна-подробно) |
| SBOM (Software Bill of Materials) | Машиночитаемый перечень всех компонентов и зависимостей артефакта, позволяющий быстро оценить влияние новой CVE. | [02-docker-manual](../manuals/02-docker-manual.MD#best-practices) |
| Volume (том) | Управляемое Docker хранилище, смонтированное в контейнер и переживающее его удаление — место для данных БД и пользовательских файлов. | [02-docker-manual](../manuals/02-docker-manual.MD#компоненты-подробно) |
