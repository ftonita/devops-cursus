# DevOps Cursus

Репозиторий учебных материалов по DevOps для менторской программы.

## Структура

```
devops-cursus/
├── manuals/            # мануалы по темам (учебный контент)
├── templates/           # шаблон структуры мануала
├── glossary/            # общий глоссарий терминов
├── ROADMAP.MD            # план тем курса
└── .claude/
    ├── agents/           # devops-writer, tech-reviewer, quiz-builder, devops-researcher
    └── skills/           # new-manual, manual-template, mermaid-diagrams, glossary-sync
```

Агенты разведены по стоимости модели: **devops-researcher** (haiku) —
дешёвый сбор фактов из веба; **devops-writer** и **tech-reviewer** (opus) —
дорогая модель для написания и ревью, где нужны рассуждения; **quiz-builder**
(sonnet) — среднее звено, синтез без веб-поиска. Писатель и ревьюер сами не
ходят в веб — они делегируют поиск фактов агенту `devops-researcher`.

## Как добавить новую тему

Просто попросите: «напиши мануал про Docker» / «создай урок по Kubernetes».
Скилл **new-manual** подхватит это автоматически и прогонит весь пайплайн
сам, без ручных шагов:

1. Определяет номер/файл темы по `ROADMAP.MD`.
2. **devops-writer** пишет черновик и сам синхронизирует глоссарий.
3. **tech-reviewer** проверяет мануал; если находит блокирующие замечания —
   они уходят обратно **devops-writer** на точечное исправление, и цикл
   ревью → правки повторяется (максимум 3 раунда), пока ревьюер не
   подтвердит `VERDICT: READY`.
4. **quiz-builder** генерирует вопросы для самопроверки и практику.
5. Статус темы в `ROADMAP.MD` обновляется на ✅ (или остаётся 🚧 с пояснением,
   если упёрлись в лимит раундов).

Для точечной правки уже существующего мануала пайплайн не нужен — можно
напрямую попросить проверить или доработать конкретный файл.
